# Интеграция PayPal для продажи лицензий на ПО

Пример реализации платежного шлюза для продажи цифровых товаров (лицензий) на Laravel 12 и PHP 8.5+. Код написан с упором на изоляцию бизнес-логики, безопасность данных и защиту от сетевых сбоев.

## Архитектурные решения

* **Инверсия зависимостей (DIP):** Все взаимодействия со шлюзом идут через интерфейс `PaymentGatewayInterface`. Приложение не зависит от конкретного PayPal SDK, что позволяет заменить платежку без изменения контроллеров.
* **Защита от двойных списаний:** 
  * На этапе создания заказа передается уникальный UUID в заголовке `PayPal-Request-Id` (идемпотентность на стороне PayPal).
  * При обработке вебхуков используется атомарная блокировка в Redis (`Cache::lock`) по ID транзакции. Если PayPal пришлет дублирующий хук из-за сетевого лага, он не будет обработан параллельно.
* **Асинхронная обработка (Queue):** Контроллер вебхуков только валидирует подпись, проверяет лок в Redis и сразу кидает задачу `ActivateLicenseJob` в очередь (драйвер Redis), отдавая PayPal статус 200. Сама выдача лицензии происходит в фоне.
* **PCI-DSS и безопасность логов:** В пайплайн Monolog добавлен кастомный процессор `MaskSensitiveDataProcessor`. Он автоматически перехватывает ключи вроде `client_secret` или `card_number` и заменяет их на звёздочки, исключая попадание приватных данных в файлы логов.
* **Сетевые повторы (Retry Strategy):** Запросы к API PayPal обернуты в HTTP Client Retry с экспоненциальной задержкой. При ошибках сети или 5xx от платежки система сделает 3 попытки с интервалом перед тем, как выбросить исключение.

## Стек
* PHP 8.5+ (Strict Types, Property Hooks, Readonly)
* Laravel 12 (HTTP Client, Очереди, Кэш)
* PostgreSQL (Транзакции на уровне БД для связки платеж -> лицензия)
* Redis (Локи и очереди)
